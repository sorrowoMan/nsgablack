# Black Framework Stack 中文开发白皮书 V6：迁移状态

本文记录 V5 正文进入 V6 分卷体系后的真实落位。它不是第二份目录，也不定义新的章节主线；全书结构以 [CONTENTS.md](CONTENTS.md) 为准，本文只回答三件事：哪些旧稿已经迁移，哪些章节经过了实质改写，哪些内容仍待编写。

## 1. 权威位置与编号规则

V6 正文的权威根目录是 `docs/whitepaper/v6/`。已经迁入 V6 的章节不再在 `v5/chapters` 维护副本，避免同一章出现两个事实来源。

正文采用“卷号 + 卷内章号”。文件名只保存卷内顺序，例如 `volume_05_composition/chapters/02_...md` 表示第五卷第二章。正文中的稳定引用优先写成“本卷第二章”“第一卷第七章”或“第八卷”，不再依赖 V5 的全书连续章号。

迁移不是简单移动文件。只要前置论证、章节职责或卷内位置发生变化，就必须同时处理标题、节号、开篇承接、内部交叉引用和结尾转场。尚未写成的章节不创建空壳文件。

## 4. 后续迁移纪律

后续每一批正文至少同时检查以下关系：

- 这一章第一次引入的概念是否已有自然问题来源；
- 开篇是否承接上一章留下的未决问题；
- 本章是否只承担一个可辨认的论证职责；
- 示例是否用于检验抽象，而不是用一个案例强行贯穿所有概念；
- 设计意图、源码静态事实、测试证据和正式运行证据是否明确区分；
- 章节标题、卷内节号、跨章引用和末尾转场是否一致；
- 框架重构尚未稳定的部分是否被诚实标记，而不是写成已经闭合。

本轮工作属于文档迁移与正文补写，没有执行代码测试、benchmark 或构建，因此不把文档中的源码描述升级为新的运行证据。
