# Black Framework Stack 工程白皮书

这套重写稿说明一个求解系统怎样从问题建模走到可运行、可定制、可组合的工程实现。读者只需具备 Python 和基本算法知识；具体概念在使用它的场景中解释。入口是仓库中的真实 Case，随后逐步拆开问题管线、算法管线、Unit、Adapter、Solver、ML 组件和共享运行底座。

本版规划十二章；截至 2026-10-08，已完成并落盘第一、二章，其余为待写章节。章内代码区分源码摘录与教学演算；演算使用人为指定的小数据，不冒充真实运行日志。最新接口见 [运行契约](../../architecture/RUNTIME_CONTRACTS_CN.md)，本轮实测范围见 [验收记录](../../development/RUNTIME_REFINEMENT_VALIDATION_CN.md)。

1. [从一个正式 Case 看完整求解过程](01_A_CASE_FROM_BUILD_TO_RESULT.md)：从 Sphere 问题、两条管线和随机提案出发，追踪装配、候选、反馈与结果。
2. [把实际问题写成目标与候选管线](02_PROBLEM_AND_REPRESENTATION.md)：变量、目标、约束、编码、初始化、变异、修复与评价的职责，并用二维数据逐步演算。
3. （待写）构建和替换算法 Unit：构建请求、schema、操作能力、显式兼容、自定义结构、codec 与恢复。
4. （待写）逐步拆开 AStar 和 VNS：节点如何进入前沿，反馈怎样关联父边，邻域怎样构建，接受与切换如何发生。
5. （待写）种群 参数和局部区域怎样支撑不同算法：NSGA2/3、SPEA2、DE、MOEAD、梯度、信赖域、MAS 与轨迹方法的结构区别。
6. （待写）Solver 怎样执行并提交一次步骤：物理尝试、预算、repair、评估、接纳、更新、提交、回滚和生命周期。
7. （待写）候选身份 反馈与持久状态：CandidateBatch、token、Feedback、Snapshot、checkpoint、分区及恢复顺序。
8. （待写）策略组合 偏置 控制器和插件：哪些组件能够组合，信息如何交换，运行能力与搜索决策怎样分工。
9. （待写）把模型训练接入同一个求解过程：真实回归 Case、Codec、Head、Provider、梯度反馈、LearningSolver 与模型交付。
10. （待写）用 Project 管理多个 Case 和计算资源：标准目录、DAG、资源需求与授权、预算、取消、并行与外部执行。
11. （待写）从嵌套训练搭到预测决策系统：逐字段读跨框架请求与结果，再推演预测、仿真和排程系统的装配。
12. （待写）扩展 调试 验证和研究：组件落点、失败定位、Doctor/Catalog、功能与效果验证以及结构方法交叉实验。

当前可先阅读第一、二章，再结合现行运行契约与正式 Case 源码。其余主题按上面的计划补写后再开放章节链接。

文中始终使用同一分工：问题管线处理候选表示与可行性；算法管线构建 Unit；Adapter 操作 Unit 并执行搜索决策；Solver 管理求解运行；mlblack 提供模型与数据语义；blackbase 提供跨 Case 的运行与资源基础。结构可替换的范围由契约决定，业务结果是否有效由具体模型、评价和实验决定。

原 V6 分卷保留用于比较旧论证与本次重写，不再作为当前白皮书的默认操作入口。API 细节仍以当前源码、正式 Case 和相应契约测试为准。
