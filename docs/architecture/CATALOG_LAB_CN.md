# Catalog 装配实验台

本机另有[Project 代码与实验工作区](../user_guide/PROJECT_CODE_WORKSPACE_CN.md)，提供原工程副本、
文本编辑、不可变修订、静态校验和按修订运行所选 Case 的最小闭环；托管只读页面保持原边界。
下文的在线装配语言与只读源码预览描述继续适用于原实验台，不应解释为所有本机入口都只能修改 JSON。

实验台从“我要解决什么问题”开始，再到“装配算法”和“看实际结果”。从 Catalog 左侧“工作区”切到“装配实验台”，或在原地址后加 `?view=lab`。

配方是可拆开的起点。当前工作区始终是一份可编辑的装配文档；手动操作、AI 草案、源码预览、下载与试跑都使用这一份文档，不各自维护一套算法实现。

## 三步完成一次实验

1. **1 · 定义问题**：用自然语言说明变量、范围、目标和约束，让 AI 生成可编辑定义；也可展开“手动编辑变量、目标与约束”直接填写。演示问题放在折叠入口中，不是必须选择的起点。
2. **2 · 装配算法**：增加算法实例，调整参数、Pool 交接与运行计划。常用设置先展示，详细参数和组件说明按需展开；也可让 AI 解释或调整装配。
3. **3 · 运行结果**：检查本次准备运行的问题，点击“开始小预算试跑”。完成后查看候选、目标方向、约束违反量、求值次数和计划进度，或让 AI 解释摘要。源码和下载在“项目源码与导出”中。

AI 在三个步骤中使用同一份内置 [框架实验引导 Skill](../../catalog/skills/framework-experiment-guide/SKILL.md)，页面标注其版本。它负责先问清问题、再解释组件与交接、最后依据结果讨论下一次实验；Skill 不增加运行权限，也不代替组件声明和正式收据。

## 从算法想法开始共同设计

三个页面是导航，不要求用户按固定顺序想问题。可以先说“我想换 GA 的交叉”“每个成员需要自己的步长”或“想加入禁忌记忆”；问题公式尚未确定时，仍可先讨论算法机制，实际试跑前再补齐可执行定义。

AI 请求会带入两类不同资料：当前在线 `assembly_catalog()` 决定可执行装配；`lab_framework.py` 从本版本白名单架构文档、源码和原有 Catalog TOML 检索静态原文，附相对路径、行号和 SHA-256。后者帮助讨论复用与扩展，不增加在线执行能力。预览与检索不导入目标组件、不构建 Unit，也不给 AI 服务数据库授权。缺失或漂移的原文明确报告；安装包携带相同白名单文档，不维护另一份手抄契约。

例如，替换交叉且候选和成员关系不变时，先检查现有变化插槽与 PopulationUnit。新增每成员步长时，再检查 `member_fields`、`on_members_changed` 与 codec；需要说明 repair、部分接纳、成员替换及恢复时怎样维护。禁忌降低评分和明确禁止候选是不同决定，需分别考虑 Bias 与算法规则；日志和检查点则复用 Plugin 生命周期。新算法不自动意味着新 Unit，也不自动意味着要重新实现 Adapter。

“设计笔记与工作区”保留用户确认或直接编辑的设计记录。AI 可建议一份更新笔记，用户单独确认后才替换；确认同时检查装配与原笔记摘要，旧建议不能覆盖之后的手改。近期聊天仍有界，已确认笔记独立保留。它可以记录待决问题与待开发组件；这些记录不构成实现或执行证据。

工作区 JSON 可下载并显式恢复装配、设计笔记和近期对话；不会恢复模型授权、运行任务或成功证据。当前页面的笔记在会话中保留，跨浏览器会话需保存并重新导入工作区。完整 Project 导出另附 `DESIGN.md` 和 `lab_workspace.json`，实际运行装配仍由 `lab_spec.json` 定义。普通 Project 的代码预览和试跑逻辑不变。

AI 对超出网页绑定范围的需求继续给出真实接口依据、具体扩展落点和待验证问题。网页提供设计与装配建议；定制 Python 组件的开发进入正式 Project/Case，并按仓库授权及验证规则进行。本机同名 Skill 同时支持这种直接开发协作，不把网页 JSON 输出格式强加给本地代码任务。

## 自然语言定义自己的问题

在“描述要解决的问题”中可以写：

> 决定产品产量 quantity，它是 0 到 10 的连续变量。利润是 8*quantity-quantity**2，希望利润最大。资源限制为 quantity 不超过 6，没有其他约束。

点击“生成可编辑草案”后，先检查 AI 提出的变量范围、目标公式和方向、硬约束，再点击“应用这份 AI 草案”。这一操作不启动算法，也不会把问题藏进一个软 Bias。对应的问题定义是：

```json
{
  "component": "problem.expression",
  "parameters": {
    "variables": [
      {"name": "quantity", "type": "continuous", "low": 0, "high": 10}
    ],
    "objectives": [
      {"name": "利润", "expression": "8*quantity-quantity**2", "direction": "max"}
    ],
    "constraints": [
      {"name": "资源", "expression": "quantity", "relation": "<=", "rhs": 6, "tolerance": 0}
    ]
  }
}
```

这个对象是装配文档的 `problem` 字段。顶层 `dimension` 与变量数一致；`repr.problem_uniform` 按每个变量自己的边界生成初值，不再强制所有变量共用 `[-2,2]`。例如产量可以是 `[0,10]`，价格可以是 `[100,105]`。问题边界修复沿用相同逐变量范围。

手动表单按“变量与范围／优化目标／约束条件”分组。修改先保留在待应用表单，点击“应用问题定义”才替换当前问题；存在未应用修改时先确认或放弃，避免试跑另一个版本。可以保留其他算法与编排，只修改问题；若目标数与当前算法不兼容，会报告冲突，不擅自更换算法。

在线入口当前支持 1～8 个连续变量、1～2 个目标、0～8 个约束。每个目标分别声明 `min/max`；每个约束声明 `<=`、`>=` 或 `==`、右值和绝对容差。公式支持声明的变量、`pi/e`、算术 `+ - * / % **`，以及 `abs/min/max/sqrt/log/exp/sin/cos`。幂指数须为 -12～12 的整数字面量；不接受属性、下标、导入、任意 Python 或网络调用。除零、对数定义域等求值错误会报告失败，不能用占位分数掩盖。

“降低费用和时间”没有说明如何计算费用与时间时，AI 会继续询问公式、变量边界或数据来源；它不能替用户捏造成本系数。整数、二进制、排列、文件／数据库数据、训练模型、仿真或外部 API 求值尚未接入这个在线入口，需要正式 Problem／Provider 扩展；可以下载 Project 后实现，不得把它们伪装成连续公式或已经连接的服务。

最大化目标的自然表达式和 `max` 声明会保留。算法按最小化约定接收 `-f`，结果表还原为用户方向的 `f`；下载记录同时保留 `raw_objectives` 与派生的 `display_objectives`。硬约束单独计入原始违反量，软偏好不擦除它。截断到变量边界不保证满足全部约束；Project 成功完成，也可能没有可行解，结果必须照实展示。

## 手动装配，不限于四个配方

1. 可保留当前 GA 起点，也可在第二步展开演示装配，选择配方后点击“载入配方”。载入会替换问题与算法；单独切换下拉框不会覆盖已经编辑的装配。
2. 先确认自定义 Problem 或演示问题，再选择初始化、变化与问题修复组件，按需要增加软偏好或 Pareto 档案。原始目标与选择偏好分开，不把 BO 当作 Bias。
3. 增加或删除算法实例，为每个实例选择组件、参数与完整变化方法。两个同类型算法使用不同实例 ID，分别持有自己的 Unit。
4. 为实例明确 Pool 输入：从母池初始化，或从已运行实例创建的视图中取解精修；方向选择支持全部或随机若干，取解数与每项精修步数分别设置。
5. 编辑串行、并行、重复和嵌套计划。先发布的视图才能被后续阶段读取；返回竞争明确指定最终结果来源，不猜接收算法。
6. 在第三步的“项目源码与导出”检查实际 `build_solver.py`、算子、问题与 Project 配置，下载完整 Project。只有点击“开始小预算试跑”才会执行。

当前在线绑定开放六族：GA / NSGA-II、MOEA/D、VNS、SA、DE、坐标模式搜索。它们可以自由选择实例、参数和受支持的交接组合，不再限定为四种配方。组件旁的能力来自 `assembly_catalog()`，显示实际可用参数、变化入口、目标数与 Pool 模式。

这六族是**本版实验台的绑定范围**，不是整个 Catalog 的组件全集，也不是框架的算法能力上限。BO、CMA-ES、MAP-Elites 等算法有各自的模型、整批更新或档案契约，尚未接入这份在线装配语言；AI 不得捏造它们的绑定或用一个 Bias 代替。任意 Python 编辑、任意模块导入和代码与图的双向同步也未开放；超出支持面的扩展可下载正式 Project 后完成。

母池初始解数、各 Unit 的成员数、每步提案数与整体逻辑预算分别配置。母池初始解数不表示池容量，也不要求所有算法的种群大小一致。Unit 在算法实际使用时建立，预览和查询组件不会提前创建结构。

## 同样的装配可以手写，也可以由 AI 起草

例如，以下文档表达 GA 搜索、SA 精修其成员、再交回 GA 竞争。省略的可选参数会按当前组件声明规范化，导出与试跑保存完整规范。

```json
{
  "schema": "nsgablack.lab.assembly/v1",
  "recipe": "assembly",
  "initial_count": 8,
  "max_steps": 20,
  "nodes": [
    {
      "id": "ga",
      "component": "adapter.nsga2",
      "parameters": {"population_size": 4, "offspring_size": 4},
      "return_from": "sa"
    },
    {
      "id": "sa",
      "component": "adapter.sa",
      "input": {
        "mode": "refine",
        "source": {"adapter": "ga", "views": "all"},
        "count": "all",
        "steps": 2
      }
    }
  ],
  "plan": {
    "kind": "serial",
    "children": [
      {"kind": "stage", "node": "ga", "steps": 2},
      {"kind": "stage", "node": "sa"},
      {"kind": "stage", "node": "ga", "action": "compete"}
    ]
  }
}
```

`input.steps` 是每项池精修的局部预算；精修与返回竞争阶段等待对应 PoolTask 完成，因此不额外填写 `stage.steps`。`multi` 表达正式 Router 的多分支提案，并不承诺 CPU 同时执行，也不允许兄弟分支读取对方尚未提交的视图。`repeat` 重用已经装配的算法实例，不每次重新构造或重放 setup。

将生产者换为 MOEA/D 时，按其稳定实例 ID 选择方向投影视图：`source={"adapter":"moead","views":"random","view_count":2}`。VNS、SA 或支持投影的模式搜索按对应方向规则精修；池保留原始多目标反馈，返回由 MOEA/D 当前规则竞争。精修还可以发布派生视图供下一层接收；父子关系通过正式视图身份维护。

## AI 全程引导与编辑

在第二步“描述想怎么调整算法”中表达修改意图，例如：

> 保留 GA 及其种群，把后面的 VNS 换成 SA。精修全部最终成员，每项两步，然后交回 GA 竞争。

点击“请 AI 调整装配”后，助手接收当前规范、基线摘要、用户描述、本版组件的真实类型、参数与交接约束，以及当前步骤和有限对话。问题步骤使用同一入口生成定义；结果步骤的“请 AI 解读结果”还接收正式 worker 作业投影出的轻量摘要，不传完整日志、数据或宿主文件。

助手可交付三种结果：完整可应用草案、需要补充的具体问题、只读解释或建议。只读解释没有草案和改动清单，不会出现可应用按钮；提问也不强行生成替代问题。对话仅保留当前页面会话最近六条、每条至多 600 字，不是持久实验记录或长期记忆。

页面先显示草案与差异。只有显式点击“应用这份 AI 草案”才修改工作区；应用不会启动试跑。若请求期间手动装配已经改变，基线摘要不匹配，旧草案不能覆盖新编辑。未支持的意图或缺少关键信息时只提出问题，不提供可应用的替代装配。

AI 草案与手动文档使用同一个 `normalize_assembly()` 和 Problem 校验器。结构检查不证明公式就是用户的业务含义，也不代表算法已经运行。结果解读先核对摘要是否属于当前装配；旧结果不能证明新修改有效。AI 可以说明页面提供的步数、求值数或失败信息，不能将小预算结果说成全局最优、算法正确性或数学证明。是否试跑由用户另行决定，执行成功由正式 Project 收据核对，不能由模型文字产生。

AI 编辑默认 UTC 每日最多 20 次，单并发，最多两个未完成请求。调用前持久预留，失败、中断与无效输出仍计一次；同一请求身份重复提交不会再次调用模型。服务重启不会清零预留额度，已丢失的结果只报告过期。预留只保存身份、摘要和时间，不保存描述、装配值、模型回复或密钥；结果暂存在有限内存历史。模型调用只进行一次，最长 60 秒，输出最多 4096 tokens、响应最多 256 KiB，不因网络故障或格式错误自动重试。

这项限额与 Catalog 后台资料整理的额度分开；它是装配请求次数上限，不是金额保证。刷新页面、读取额度或刷新已提交草案不会再次请求模型。

## 一份正式项目来源

`catalog.lab_assembly` 拥有封闭装配文档 `nsgablack.lab.assembly/v1`、可用绑定目录、规范化和源码生成。`catalog.lab_project` 保留原配方入口，并将自由文档导出为共享正式 Project→Case→Scaffold。

源码预览、ZIP 下载与运行器共用同一个导出实现。算法实际运行复用 SearchPlanAdapter、PoolTask、各算法 Unit、现有 Router、提交事务与 Project L0；网页没有再实现一套算法循环。旧固定配方参数 `nsgablack.lab.spec/v1` 仍可读，但新的可编辑工作区使用 assembly 文档。

未知字段、越界数值、错误类型、缺失来源、未发布视图、实例所有权冲突和不支持的组合会拒绝。装配 JSON 不能提交任意代码、命令、模块路径、服务 URL 或文件地址。导出项目保留 canonical `build_solver.py` 与 `run_solver.py`；下载后可在对应目录修改 Problem、变化或选择函数，并继续使用正式框架入口。

## 三个服务的边界

托管部署分别设置三种职责：

- **Catalog reader**：保留数据库 SELECT 和既有 simon 入口鉴权；预览、导出，并使用两个固定内部客户端授权提交运行或 AI 编辑。没有模型 key、writer、宿主工作区或 Docker socket。
- **试跑 worker**：只接收校验后的配方或 assembly JSON，在临时目录导出项目并启动正式 Project CLI。没有模型 key、数据库授权和 AI 服务 token；Project L0 是资源授权来源。
- **AI assistant**：持有单用途模型配置及自身私密额度目录；只生成结构化装配草案，没有数据库凭据、运行服务授权和执行接口。不把模型 key 放入试跑进程。

浏览器不能指定服务目的地、配置文件或凭据。服务端私有 HTTP token 通过只读部署文件传递，不进入浏览器、URL 或源码。运行服务仅使用内部网络；AI 服务只需固定模型 HTTPS 出站，不开放公网服务端口。未配置 AI 时手动装配与试跑仍可使用；托管环境未配置试跑服务时只能预览与下载，不回退到网页进程执行。

试跑单并发，最多三项未完成任务，每项 60 秒；保留至多 16 条轻量记录，完成约一小时或服务重启后可能过期。项目与运行 JSON 应下载保留。页面与队列复用请求身份，刷新不重复执行；参数修改不改变正在运行的旧作业。

## 运行成功的证据

运行器核对本次标准 Project manifest、Case 身份、成功状态和退出码、实际资源绑定、报告 Artifact 的发布收据与摘要，再按本次 Problem 核对原始目标和约束违反量。自定义表达式与导出 Case 共用同一份公式解释器；页面还原显示方向，不改写池中的算法评分。成功标签不能仅凭退出码零、模型建议或用户输入产生。

结果显示提交逻辑步、实际求值次数、原始目标、Pool、Unit 和有界日志。等待、拒绝与失败不制造逻辑代；超时清理本次进程树，不重跑评估。修改参数后，旧结果标记为上一次装配。整体预算可能先耗尽，`plan_completed=false` 会明确报告只完成部分阶段。

发布验收除了四种配方，还执行自由 GA→SA→GA、MOEA/D 方向精修、多算法并行后精修、嵌套方向视图，以及自定义最大化问题。自定义场景用不相同的变量范围和故意无法满足的硬约束，独立重算评分与正违反量，确认运行成功不会抹掉不可行事实。验收核对实际算法类型、正式 L0、原始评估及计划完成，证明这些特定装配在本次参数下真实运行，不证明任意组合或数学正确性。组件浏览和验收页面预览继续禁止模型生成及 Unit 构造；真实模型生成另有显式、有限验收。

## 对应实现

- `catalog/lab_assembly.py`：可编辑装配目录、校验和正式代码生成。
- `catalog/lab_problem.py`：声明式问题、公式解释、逐变量边界及显示方向。
- `catalog/lab_project.py`：原配方入口及统一项目导出。
- `catalog/lab_runner.py`：标准 Project CLI 和收据核对。
- `catalog/lab_jobs.py`：有限试跑队列及提交身份。
- `catalog/lab_assistant.py`：结构化 AI 草案、显式应用门及持久额度。
- `catalog/lab_guide.py` 与 `catalog/skills/framework-experiment-guide/SKILL.md`：固定版本引导与有限阶段上下文。
- `catalog/lab_service.py`：独立 runner / assistant 私有服务角色。
