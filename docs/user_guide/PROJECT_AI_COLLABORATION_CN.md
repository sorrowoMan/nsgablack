# 与 AI 协作已有 Project

实验台的“已有 Project 协作”用于继续已有的正式项目。它与“自由装配”共用页面风格，但直接复用 Project／Case 的问题、数据、管线和求解器，不受演示表达式入口的变量数量限制。

## 一次完整协作

1. 在实验台切换到“已有 Project 协作”，选择服务提供的项目。
2. 描述业务意图，例如“沿用这个排程模型与数据，先以小预算跑一次；保持原始目标与约束”。AI 可以列文件、读取源码和说明、检查 CSV／XLSX 结构，并读取 Case 实际声明的参数。
3. AI 通过工具提出结构化配置。页面展示方案、来源与工具记录。点击“采用这个方案”后，该方案成为当前配置。
4. 点击独立的运行按钮。运行器核对方案摘要和项目版本，在隔离副本中调用原 Project／Case 入口，由 L0 发放资源；原项目与数据不被修改。
5. 完成后查看本轮原始反馈、业务审计与实际数据。继续向 AI 提问时，页面只传试跑身份，AI 从独立的只读通道回读真实结果。

长文件可以按关键词定位后再读相关行。对话达到上下文预算时，服务显式收缩较早的只读正文，保留来源、文件摘要与行号；需要细节时重新读取，不生成一份未经核对的“记忆事实”。页面显示模型和工具进度。

采用方案不会自动运行。修改方案后，旧结果仍可查看，但不会作为新方案已经运行的证据。失败与超时也可以交给 AI 分析。

模型可能误述“已校验”，实际以右侧工具交付的结构化方案为准。没有该方案时，页面会明确提示本轮未交付新配置，文字建议不会替换已采用配置。运行后可下载经过大小与摘要核对的实际导出 ZIP；整数 CSV 和浮点审计的统计口径应分别核对。

## 与已有模型的关系

一个新的业务偏好不自动意味着新建 Problem、Unit 或 Adapter。先读取实际实现，再决定调整原始目标、选择偏好、候选构造还是算法决策。已有多目标不能因为用户概括了两个诉求就被删成双目标。

以排程为例，日产量平滑、某机种连续生产、机种覆盖和总产量各有具体定义。参数有类似名字，不代表这些指标等价。数值建议只是下一次实验配置，效果必须依据本轮数据和收据判断。

## 当前支持范围

- 只读取部署者明确提供的可信正式 Project。模型使用项目句柄和相对路径，不配置宿主目录或外部地址。
- 数据结构检查支持有界 CSV／XLSX／JSON 预览，保留文件 SHA 与版本；不执行工作簿公式。
- 配置复用 Case 可静态核对的参数类型、默认值与 choices。未声明的参数、任意文件路径、Python 和 shell 命令不作为执行输入。
- 首版试跑使用单 CPU 线程、无 GPU、有限步骤和时间。资源继续属于正式 L0，AI 不自行申请额外设备。
- 日志、临时目录和产物与源码分离。运行依据包含实际项目版本、读取的数据摘要、原始反馈与正式结果发布收据。
- 新算法实现、任意源码编辑、缺少参数契约的 Case 和额外后端安装仍是明确的开发工作；助手不能将建议写成已执行。

## 部署

助手服务负责资料读取和模型调用，运行服务负责正式 Project 执行。模型凭据不进入运行器。

运行器可以配置独立 `result_token`。该令牌只允许读取 `/project/jobs/<id>`，不能提交运行、读取旧装配任务或调用其他接口。助手通过部署者配置的 `NSGABLACK_PROJECT_RESULT_CLIENT_CONFIG` 使用此只读通道；浏览器不能指定模型地址、文件根或运行服务。

默认源码发布包不携带业务数据。需要真实 Case 数据时，部署者通过 `package_context.py --project-asset <正式Case内的CSV或XLSX>` 逐文件显式选择，并将其 SHA 记入发布清单。没有相应资产时不得用生成的模拟数据冒充真实输入。

## 验收口径

分别记录：模型实际读取的资料、经校验的方案、独立试跑、结果回读、需求变更后的新方案和运行。工具调用次数与用户请求预留次数分别记录；请求去重不等于重试模型，服务不会自动重试不确定的模型 HTTP 请求。

小预算验收证明协作链路、来源与执行成立，不直接证明达到历史长预算结果或全局最优。
