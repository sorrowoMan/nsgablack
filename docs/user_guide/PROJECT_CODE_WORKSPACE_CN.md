# Project 工程实验工作区

这个入口把真实标准 Project 的文件编辑、修订保存、静态校验、正式 Case 运行与结果回看放在同一工作区。
它使用现有 Project/Case/L0、Solver、Pool 与运行收据，不建立另一套算法运行循环。

工作区默认使用深色主题。左上角“界面”可以切换深色、浅色或跟随系统；代码编辑器、小窗与工具面板一起切换，保留当前草稿和编辑位置。本次会话保留选择；新会话仍以深色开始。
参数和结果中的原生数据表沿用服务启动的深色底色；在浅色外壳中仍显示为深色表格，不影响内容、筛选或记录。

## 启动

在已安装框架、Streamlit 和相应 Project 依赖的本机终端中执行：

```powershell
python -m nsgablack.catalog.lab_workspace --port 8633
```

打开 `http://127.0.0.1:8633/`。默认来源为本机源码中的 `examples/cases/`，修订和运行历史保存在
用户目录下的 `.nsgablack/project-workspaces/`。普通安装没有完整示例时，登记你自己的标准 Project：

```powershell
python -m nsgablack.catalog.lab_workspace `
  --project-root "mine=C:\MyProjects\production_scheduling" `
  --storage "C:\MyExperiments\workspace-data" `
  --port 8633
```

来源可以是一个完整 Project，或直接包含若干 Project 的目录；`--project-root` 可重复使用不同名称。
来源和工作区存储目录必须分开。服务器地址固定为本机回环地址，浏览器不提交宿主目录或运行命令。

本机已经显式配置工作区时，原 Catalog 的本地实验台也提供“Project 代码工作区”工作方式。
托管只读 Catalog reader 本身不执行工程。另行部署的工程实验前端可以经认证连接本机运行器，
界面在云端，代码、数据、修订与求解仍在本机；见[部署说明](../../deployment/workspace/README.md)。

## 从真实工程开始

1. 点击左侧“打开工程”，从登记来源选择 Project，创建工作副本。只有允许的源码和数据闭包进入副本；原项目文件不修改。
2. 左侧显式选择运行 Case，在顶部“文件范围”切换“全部代码”“搜索与编排”“问题与数据”“候选处理”“偏好与能力”，从左侧文件树打开源码。
   “全部文件”还可查看公共装配及其他 Case。源码中的定义、选择/变化/池维护等调用有实际行号，可展开附近代码。
3. 中央代码编辑器提供行号、Python／JSON高亮、Tab缩进、撤销／重做和查找。通过“修改差异”核对改动，在“编辑器选项”可填修订说明，使用编辑器内的 Ctrl/Cmd+S 或“保存”。可以一次保存多个文件的草稿；左侧“版本历史”可读取旧修订。
4. 点击顶部“试跑设置”，右侧显示这个 Case 的真实参数声明。未勾选“调整”的参数沿用工程原值；
   勾选后可用数值、开关或枚举填写。复杂输入可显式切换 JSON，仍不能传入未声明参数。
5. 先做静态校验，再点“开始试跑”。提交后保留当前代码与工具面板，下方显示本次运行状态；需要时点“查看本次结果”，再查看原始目标、违反量、实际步数、评估次数、业务标量与日志。“返回代码”继续原稿。
6. 选“对照实验”核对两次参数、预算、运行计数和报告中的标量业务指标；原始多目标不自动求和或判断优劣。

右侧关闭按钮让编辑器恢复完整空间；再次打开会保留本 Case 的参数草稿、步数、超时和随机种子。
既有工程首屏只读工作副本元数据和当前文件；来源列表、参数声明及实验详情分别在打开对应窗口／面板后读取。
来源浏览只列目录信息，创建副本时仍核对源码、数据闭包与摘要，列表不是装配或运行验证结果。

默认参数超过快速试跑上限时，页面要求明确填写本次覆盖值，不自动缩小种群或修改业务数据。
这些上限属于试跑资源策略，不是 Problem 的业务约束。完整原模型仍可从正式 Project 入口运行。
版本、摘要与运行身份保存在详情，不要求用户记住编号。历史源码导航只读取对应历史内容，不能混入新草稿。

数据文件显示只读摘要，不在代码文本框中编辑。第一版修改已有文本文件，不包含文件删除、依赖安装或任意终端。
保存允许尚未写完的 Python 草稿；有语法错误时静态校验失败，不能交给运行器执行。
未保存草稿可跨区域、文件和工作副本切换，但仍位于浏览器会话；刷新或关闭浏览器前应保存。

## 编辑时查组件和找位置

- 点击顶部“查组件”，直接在小窗按名称或用途搜索。关闭后继续原代码；需要持续对照时，点“固定到右侧”。右侧默认“接入”先给出原文中的准备、位置与主代码，完整原文在“完整用法”标签，也能再次弹出小窗。
  “怎么用”提供发布说明及原文代码，代码块右上角可复制；“参数与接口”和“相关组件”提供声明资料。
  关系可以在小窗内跳转，再返回上一组件。搜索、选中的片段和本次会话收藏会保留；关闭后仍在原文件与草稿。
- 小窗读取当前发布镜像附带的资料，源码说明和运行收据分别标注，不发起 AI 请求、不调用组件构造器、不自动插入代码。
  本机没有这组发布资料时会明确提示不可用，不悄悄展示另一份不完整目录。
- “查找工程文件”按整个工程的文件名／路径匹配，搜索时保留当前文件。打开另一个 Case 的文件只改变浏览位置，运行目标保持原值；页面提示正在浏览的 Case，并提供显式设置运行目标的动作。
  “最近查看”可直接回跳，未保存的多文件草稿继续保留。手动选择运行 Case 时会打开它自己的装配入口并清空旧文件搜索。顶部职责分类不会关闭已经打开的文件。
- “定位函数与装配调用”和“查看待保存差异”采用浮层，避免把编辑器向下推。
  当前静态诊断可直接打开对应文件和附近行；旧修订或新草稿已有变化时，旧诊断定位会禁用。
- 编辑区的“查看本次结果”可跳到同页结果区，运行不会强行滚动或切换正在编辑的文件。

参数表单与 JSON 现在编辑同一份 Case 覆盖值；保存源码推进修订后也保留这些值，再按新声明检查。
无效 JSON 原文单独保留，不能运行；切回表单时明确使用上一次有效值。
字段删除、类型或范围变化不会自动丢弃原覆盖，可以逐项撤销，或点击“恢复 Case 默认参数”明确清空本 Case 覆盖。

## 编辑中的审查与修复

编辑时会自动进行 Python 语法解析，在代码对应行标记错误。点击顶部“审查”可以定位问题、查看当前文件的静态装配调用线索，
再查对应组件的使用说明。调用线索只描述源码，不证明工厂已执行、组件兼容或算法正确。

当前自动修复只覆盖明确、可核验的缺冒号情况：先显示一字符差异，整份修复候选必须可解析；点“应用到草稿”才采用。
原稿发生变化时拒绝套旧建议，应用后可以“撤销这次修复”。两步都不自动保存或运行。
缩进、括号和算法逻辑不会靠猜测自动改写。复杂AI审查／修复尚未接入，工作区不会调用DeepSeek。

## 修订与结果的关系

每个工作副本有自己的身份和当前修订。每次保存记录父修订、源码/数据摘要和文件清单。
相同内容的数据文件共用不可变 blob，不因为修改一个函数就再次存一份 XLSX。

例如：

```text
修订 A：原始平方和问题 → 运行 1 → 原始目标 0.625
修订 B：给目标加 1      → 运行 2 → 原始目标 1.625
```

这两个分数表示问题定义不同，不能用来断言算法优劣。这个小例子只用来确认代码改动实际进入了对应运行。

运行提交时冻结修订、Case、参数、预算和随机种子。运行中继续保存，不改变正在执行的修订。
查看旧结果时页面显示其所属修订，不能把旧结果当成新草稿的验证。
编辑端依据保存时的基线做并发检查；另一个页面已推进修订时，旧草稿不能直接覆盖它。

工作区与作业记录保存在本机磁盘，刷新页面后可以回看。进程重启时，先前未完成的作业标记为中断，
不会自动重跑 Problem 或凭旧队列记录声称运行成功。继续实验需要显式提交新运行。

候选表目前是报告中的最近接纳历史，不代表 GA 最终成员或 VNS 最终交付。
逐解展示“最终成员 → 精英池 → 精修 → 返回接纳”需要进一步接入正式交接证据。
两次数据一致性只核对报告明确登记的文件摘要；外部输入未声明时，页面不声称完全可比。

## “静态校验”和“运行”分别做什么

静态校验核对冻结文件、Python 语法、标准 Case 与已声明的参数；不执行 builder，不构造 Unit，也不运行算法。
它不能证明组件兼容、领域约束或算法正确性。真正的装配和求解发生在显式运行后。

运行复用现有 `lab_project_trial`：从冻结修订生成独立执行副本，包装原 builder，
由正式 Project/L0 发放单线程、无 GPU 的资源授权，按已确认预算运行所选优化 Case。
验证正式运行身份、收据、原始反馈与资源绑定后才报告成功。失败、超时和中断各自保留真实状态。

这是**所选 Case 的有界试验**，不承诺执行原 Project 的全部多 Case 阶段或依赖图。
具有额外 Artifact 前置依赖的 Case 仍需要完整项目编排。ML Trainer、外部 Provider、缺失数据或未安装依赖也不因打开工作区而自动获得支持。

已有 CLI 参数只开放静态可检查的声明值。没有解析器的标准 Case 可显式采用“无额外参数”模式；
该模式只允许空参数对象，步数和 seed 仍由正式控制面设置。工作区不猜测任意 config 字段。

## 一个可以照做的小例子

选择 `catalog_fixed_candidate`，创建工作副本，打开：

```text
cases/fixed/problem/__init__.py
```

保持候选 `[0.25, 0.75]`，先保存原版并运行 `fixed` Case，使用一步预算。
然后把 `evaluate()` 的返回改为：

```python
return 1.0 + float(np.sum(np.asarray(x, dtype=float) ** 2))
```

保存新修订，静态校验后再次运行。检查两份记录的修订身份不同；原始目标分别为 `0.625` 和 `1.625`，
违反量为 0，实际求值各一次，L0 资源绑定为当前运行。原示例目录中的文件保持原状。

进一步改自己的变化方法时，只修改工作副本中的实际算子函数及必要装配；
Pool 引用、Unit 更新、repair 对账和提交仍使用组件本来的契约，不由编辑器偷偷代办。

## 使用范围

这个入口用于运行本机用户信任的 Python 工程。独立进程、超时和净化环境是运行管理，**不是任意代码安全沙箱**。
它不会调用 DeepSeek，也不自动编辑代码；需要 AI 协作时，可先在本地开发工具中审查补丁，再纳入工作区。
Catalog 的源码资料、AI 整理记录与这个工作区的实际运行证据仍分别统计。
