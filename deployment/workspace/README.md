# 云端界面与本机执行

Project 工作区可以把浏览、代码编辑和结果展示部署到服务器，把工程、修订与求解保存在用户自己的电脑。
托管 Catalog reader 不执行用户工程；另一个轻量前端经认证连接本机 Agent。

## 运行链路

```text
simon 登录看板
  → /apps/framework-workspace/（原账号访问检查，HTTP 与 WebSocket 均检查）
  → 云端 Streamlit 客户端（loopback 18645）
  → SSH 反向连接（服务器 loopback 18640 → 本机 loopback 8640）
  → 本机 Agent：WorkspaceStore / WorkspaceRunner
  → 原 Project / Case / L0 与已绑定修订的正式运行收据
```

浏览器不接收 Agent token，不选择服务器地址、本机目录或命令。客户端配置由部署者挂入云端服务，
本机来源仍由 Agent 启动配置登记。认证 RPC 仅提供工作区和运行器的明确方法，不公开 `materialize`、
任意属性、宿主文件或 shell。断线不回退到云端执行，不自动重新提交实验。

电脑需保持在线。电脑休眠或连接中断时，界面提示本机不可连接；连接恢复后继续读取原有修订与历史。
算法运行、数据文件及持久化实验位于本机，因此主要求解开销也在本机；云端仍需要承担界面渲染和传输开销。

## 本机连接器

操作员准备私有 Agent 配置与连接配置后运行：

```powershell
python -m nsgablack.catalog.lab_workspace_connection --config "C:\Users\hp\.nsgablack\workspace-link.json"
```

Agent 配置包含随机认证 token；连接配置仅引用它，并声明存储、可信工程来源、SSH 身份文件和固定端口。
不要把配置、SSH 私钥或 token 提交到源码仓库。连接器启动一次 Agent，SSH 断线后有界退避重连，
不因重连重建工程、重跑作业或调用模型。停止时仅关闭本连接器拥有的连接与 Agent：

```powershell
python -m nsgablack.catalog.lab_workspace_connection --stop --config "C:\Users\hp\.nsgablack\workspace-link.json"
```

本机原 `8633` 界面也可配置为同一个 Agent 客户端，两个界面共享唯一队列，避免各自建立运行所有者。
这是用户信任工程的执行入口，现有独立进程和资源预算不等于任意代码安全沙箱。

## 云端前端

Dockerfile 基于已经核验的 Catalog 镜像，只覆盖十三个工作区客户端、界面与只读展示模块，以及离线代码编辑器静态资源，不复制用户工程、数据库、
模型配置或本机执行器。部署者通过 `BASE_IMAGE` 指定实际已有镜像摘要，并保留独立的来源 manifest。

服务采用非 root、只读文件系统、无额外 capabilities、有限 tmpfs 和资源上限；不挂载 Docker socket、SSH key、
Catalog 数据库或模型密钥。主机网络仅为连接反向转发的 loopback 端口，Streamlit 自身仍绑定 loopback。
入口登记为独立 `framework-workspace`，仅允许 simon，复用原看板鉴权与身份头隔离，不开放新的公网端口。

`verify_frontend.py` 逐文件核对覆盖层和编辑器资源来源，实际渲染远程客户端页面，并拒绝服务内创建本地 runtime 或进程。
Python AppTest明确使用纯文本后端契约检查模式，不声称执行编辑器JS；CodeMirror的颜色、快捷键、消息同步、修复和文件切换，
另在全新headless浏览器与独立内存测试工程中验证，不能操作用户浏览器或把模拟结果当真实算法收据。
按钮验收使用无顶部说明条的真实页面布局，普通物理点击核对组件身份与内容变化；不能用 force 点击或只检查无异常来替代。固定标题层的透明区域不接收指针事件，实际侧栏控件仍可点击。
健康检查只检查前端自身可用，电脑离线不应把云端页面误报为不可用。完整部署还应验证：

- 通过云端界面保存修订、在本机获得实际结果并验证相同修订摘要；
- 普通匿名和其他账号无法访问，HTTP/WS 都经过原账号检查；
- 原 Catalog/AI/执行 worker 等实例保持不变；
- Agent token 不进入浏览器和验收报告；
- 空闲与一次实际运行期间的云端资源使用，按真实测量记录。

当前执行范围仍是[本机工作区手册](../../docs/user_guide/PROJECT_CODE_WORKSPACE_CN.md)中所选 Case 的有界试验，
不把新连接方式描述成完整原 Project 多 Case 编排能力。

## 工程实验页面

页面采用顶部文件分类、左侧文件树与修改清单、中央代码编辑器。文件标签可回到最近打开的源码。
默认深色主题；左上角“界面”可切换深色、浅色、跟随系统，外壳与独立编辑器同步换色，不重建文本或撤销历史。服务原生主题也以深色启动，避免首屏先出现白色。
顶部可保存、审查、查组件、打开试跑设置和实验结果。查组件先打开小窗，按需固定右侧；运行／审查工具按需出现，结果使用独立视图。
浏览另一个 Case 的源码不切换运行目标；页面提供明确的“设为运行目标”。职责分类不关闭已打开文件。
提交试跑后代码仍在原位，底部轻量状态条只对活动作业轮询状态，完整结果按需读取。
工具收起后保留预算、随机种子及 Case 参数草稿，结果返回代码后继续原来的修改。
编辑器静态资源随包提供，无外部CDN；支持行号、Python／JSON高亮、Tab缩进、撤销／重做、查找、定位与Ctrl/Cmd+S。
父界面先捕获带身份的最新文本，再执行既有修订CAS保存；跨文件快切与重挂共用确认后的消息序号，不把重复保存请求变成第二次写入。
语法诊断在编辑器内标记。代码审查仅静态读取；当前确定性修复只对Python明确缺冒号且完整修复后可解析的情形提供差异预览，
用户明确应用后只进入草稿，可撤销，不自动保存、构造组件或运行。复杂逻辑修复和AI审查尚未接入，此入口不调用DeepSeek。
来源、参数和作业详情分别在用户打开对应区域后读取，不因关闭的浮层执行全部扫描。
参数采用表单，勾选后才覆盖原值；JSON 保留为显式切换的高级输入方式。
修订编号、文件摘要和运行证据放入详情。接纳历史继续按实际范围标注，不冒充最终成员。
源码位置仅由文件清单与 AST 生成，不执行 Project，也不推断任意 Python 的运行图。
当前工作副本的 AI 修改、完整 Project DAG 运行和逐解精修交接可视化仍未接通；页面明确列出范围。

更新时先在另一个 loopback 端口启动候选客户端，核对来源摘要并用 Streamlit AppTest 验证实际远程读取，
再替换工作区前端。Catalog、AI 服务、执行 worker 和看板鉴权不因页面更新而重启。
存在活动编辑连接时，新版在独立端口启动，仅切换 gateway 的工作区 upstream 并平滑 reload；旧进程与已有连接保留，
避免强制中断未保存的编辑。旧页面刷新前仍应先保存草稿；新请求进入新版，原页面断线重连不能保证继续旧服务内的会话。
如果更新来源枚举实现，先确认无排队／运行作业，再有序重启本工作区 Agent，保留配置、存储和凭据；
前后核对工作副本修订与历史，不通过重建工程来迁移。
保留旧前端容器及其镜像，可回切；不要删除本机存储或重新创建工作副本。

组件速查直接读取同一基镜像发布的 `knowledge-packets.json`、`knowledge-sources.json` 和 `examples.json`，
核对摘要与口径后提供搜索、完整用法、可复制原文、参数和显式配套关系。无需给前端增加数据库或模型凭据。
小窗关闭、关联返回、搜索与会话收藏不修改工程；代码复制后仍由用户决定放置位置。
发布验收必须按实际 `AppTest.from_file` 入口打开小窗、搜索 CompositeAdapter、检查代码片段并关闭返回原文件，
同时禁止 RPC submit/save/create 等远程写入，避免把页面检查变成新实验。
